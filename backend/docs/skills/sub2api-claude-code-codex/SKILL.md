# sub2api Claude Code Codex

This skill is the short entrypoint for running Claude Code through a local Headroom + `sub2api` Anthropic-compatible proxy chain backed by the user's OpenAI/Codex/ChatGPT subscription. Keep this file lean; load the reference files only when the task needs those details.

This is the single owner for stack installation, repair, and fleet-wide provider switching. Do not install or recreate a separate provider-switcher skill.

## Default Hybrid Install Profile

Use this profile unless the user explicitly asks for a different model, port, or risk tradeoff:

```text
Fork: https://github.com/stgmt/sub2api
Headroom fork: https://github.com/stgmt/headroom
Branch: main
Verified main commit: use `git log -1 --oneline` on https://github.com/stgmt/sub2api main after each stack update
Fixed issue: https://github.com/stgmt/sub2api/issues/1
Image: sub2api-codex:local-token-usage
Headroom image: headroom-sub2api:0.31.0 built from `HEADROOM_GIT_REPO=https://github.com/stgmt/headroom.git` at pinned `HEADROOM_GIT_REF` using `HEADROOM_RUST_TOOLCHAIN=1.88.0`, plus RTK, lean-ctx, TokenSave, ast-grep, difft, scc, and idempotent downstream embedding-server plus Claude Code streaming-overlap patch guardrails. NVIDIA installs use `docker-compose.gpu.yml`, the `gpu` image stage with pinned CUDA PyTorch, and Headroom's native batched `pytorch` Kompress backend; CPU remains the fallback.
Docker compose project: sub2api-codex
Deploy profile: deploy/claude-code-codex-headroom
Claude base URL: http://127.0.0.1:8787
Claude chain: Claude Code -> Headroom 127.0.0.1:8787 -> Docker DNS http://sub2api:8080
Direct sub2api URL: http://127.0.0.1:18081 for admin UI, diagnostics, and non-Claude clients only
Headroom MCP: user-level Claude MCP named `headroom`, launched through `wsl.exe -e docker exec -i headroom-sub2api headroom mcp serve --proxy-url http://127.0.0.1:8787`
Headroom savings profile: agent-90, target ratio 0.10, context tool RTK, code-aware compression on, memory on, embedding server on, output shaper on, effort router off so client-selected effort is preserved
RTK execution: pinned RTK 0.42.4 on Windows plus WSL or on the native Linux host that runs Claude Code; use one global Claude Code `PreToolUse(Bash)` hook and share host history with Headroom at `/root/.local/share/rtk` when both run on the same Docker host
Host state root: `${SUB2API_STATE_ROOT:-./data}` in the deploy profile. All state must be host bind-mounted there, not stored in Docker named volumes.
Codex OAuth self-heal: sub2api reads `SUB2API_OPENAI_CODEX_AUTH_FILE=/app/data/codex-auth.json`; setup and the repeating self-heal task copy a validated host `%USERPROFILE%\.codex\auth.json` into `${SUB2API_STATE_ROOT}/sub2api/codex-auth.json` without printing secrets. When `SUB2API_STATE_ROOT` is a Linux absolute path, Windows must translate the source with `wslpath`, stage it inside WSL, chmod `0600`, atomically rename it, and verify host/WSL SHA-256 equality. Never create a shadow `C:\home\...` tree.
Headroom persistence: `/root/.headroom` stores `ccr_store.db`, savings, and logs; `/root/.cache/headroom` and `/root/.cache/huggingface` store warmed local tool/model/embedding caches; `/root/.local/share/rtk` exposes the host RTK history to Headroom. These paths must be host bind mounts.
Windows autostart/self-heal: use one scheduled task named `Sub2API Codex Proxy Stack Autostart`, not a Startup-folder `.cmd` and not a separate `headroom-proxy` task. The task must launch `ensure-sub2api-proxy-stack.ps1` through the zero-window `run-hidden.vbs`/`wscript.exe` wrapper with `RunLevel=Highest` at logon and every minute; direct interactive `powershell.exe` actions can flash a console and steal focus. Its healthy path probes same-host plus diagnostic Hyper-V bridge `/health`; the bridge is fail-closed only with `HEADROOM_HYPERV_REQUIRE_BRIDGE=1` or `-RequireHyperVBridge`. Its failure path calls the canonical stack start script to wake WSL, restore Docker compose, refresh dynamic bridge addresses, and self-heal stale WSL `ext4.vhdx` attach locks.
Provider profiles: setup installs the bundled `claude-route` command from this skill. The same single autostart task reconciles its stored generation; do not add a second provider task. Always run `claude-route status` before describing the live profile because it may intentionally be `anthropic-only`, `qwen-only`, `alibaba`, `chatgpt-only`, or `hybrid-current`.
Profile verification: `verify-claude-code-sub2api.ps1` must derive every picker alias, the SDK model, group name, and fallback policy from the active client environment. Native `anthropic-only` means `claude-subscription-only`, suffix-free server model IDs, and no automatic model fallback; both native Windows RTK and the WSL bridge are valid when their live hook probe rewrites the command correctly.
Autostart safety: normal health ticks use `docker compose up --no-recreate`; `--force-recreate` is recovery-only. Before recovery, read Headroom `/stats.proxy_inbound.active`; the `/stats` observer itself is included in that raw gauge, so subtract exactly one and retain both `raw_active` and observer-adjusted `active` in evidence. Active user traffic or an unproven running state yields `recovery_deferred`, while recreation is allowed only when adjusted activity is zero or a required container is stopped/missing. A built Headroom image is rolled out by this same watchdog only at a proven idle window, with `--no-deps --force-recreate headroom`; active/unknown traffic yields `headroom_image_rollout_deferred`.

Main model: gpt-5.6-sol
Small-fast/compact/delegated SDK model is profile-dependent: `chatgpt-only` v5 uses `gpt-5.6-luna` with the profile's configured effort; Qwen/Alibaba profiles use `qwen3.8-max-preview` when their profile explicitly selects it
Fast mode: keep Claude Code's visible model family OpenAI/Codex only. `ANTHROPIC_MODEL` and the primary picker slot are `gpt-5.6-sol`; picker/delegated slots use `gpt-5.6-luna`. If a client emits the Fast signal, sub2api selects `fast_mapped_model=gpt-5.6-luna` and serializes the user-facing Codex `fast` setting as wire-level `service_tier:"priority"`, matching the native ChatGPT/Codex OAuth client. Set both `CLAUDE_CODE_SKIP_FAST_MODE_NETWORK_ERRORS=1` and `CLAUDE_CODE_SKIP_FAST_MODE_ORG_CHECK=1`: with `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` and a custom `ANTHROPIC_BASE_URL`, the second gate is required to avoid the client's `Fast mode is currently unavailable` response. These variables only bypass the client-side availability check and do not claim provider capability. Accept Anthropic `anthropic-beta: fast-mode-2026-02-01` and body `speed:"fast"`, normalize the alias to `priority` on Responses and raw Chat Completions fallback routes, and log `openai_messages.fast_mode_forwarded` only after the final policy body is known. Read the upstream response tier separately: `usage_logs.service_tier` is reconciled to the provider's returned tier when available, while `openai_messages.fast_mode_provider_confirmation.request_service_tier` records intent. Only `provider_confirmed=true` with the upstream response tier `priority` proves the requested Fast wire tier was honored; `default` means the provider declined/downgraded it.

Do not confuse the Codex control-plane setting with its wire value. OpenAI's [Codex Speed documentation](https://developers.openai.com/codex/speed) defines the setting as `service_tier = "fast"` plus `[features].fast_mode = true`, while official Codex traces/issues show the OAuth request serialized as `service_tier:"priority"`: [openai/codex#30413](https://github.com/openai/codex/issues/30413), [openai/codex#32191](https://github.com/openai/codex/issues/32191). The [Priority Processing FAQ](https://help.openai.com/en/articles/11647665-priority-processing-faq) is about public API billing, so do not infer subscription billing from the name alone. A returned `default` means the provider declined/downgraded the requested tier, not that the proxy may relabel it as Fast. Do not map to `gpt-5.5-fast` or invent a `gpt-5.6-fast` slug: model routing and service tier are different controls.
Automatic-route availability fallback: gpt-5.6-sol with effort high, only for compact/subagent/claude -p after a terminal Alibaba Token Plan quota response or while its persisted account quota circuit is open
Published model families: GPT/Codex plus Alibaba Token Plan only; do not expose real Claude/Fable passthrough aliases in `/v1/models` for this profile
Picker category defaults: Qwen/hybrid profiles pin Opus/Fable/Sonnet/Haiku to Qwen high (`qwen3.8-max-preview`); `chatgpt-only` exposes only GPT/Codex IDs and keeps its delegated picker slots on Luna.
Provider families: GPT/Codex models route to the OpenAI/Codex OAuth account; qwen*/glm*/deepseek-v4-pro route to the Alibaba Token Plan Anthropic-compatible account.
Official model windows: GPT-5.6 Sol/Terra/Luna = 1.05M; GPT-5.3-Codex-Spark = 128k and text-only; Claude Fable 5/Opus 5/Sonnet 5 = 1M; Claude Haiku 4.5 = 200k
Hybrid client context target: CLAUDE_CODE_MAX_CONTEXT_TOKENS=370000, CLAUDE_CODE_AUTO_COMPACT_WINDOW=340000. Anthropic-only v4 sets both fields to 1000000 and uses `claude-opus-5[1m]` plus `claude-sonnet-5[1m]` on the Claude Code side, because a local LLM gateway otherwise budgets even native 1M models at 200k. Keep the server-side sub2api model IDs suffix-free; Claude Code strips `[1m]` before transport.
Compact model: qwen3.8-max-preview through group messages_dispatch_model_config.compact_mapped_model; compact requests must cross-route from GPT/Codex to the Alibaba Anthropic-compatible account before provider classification
Reasoning: main interactive GPT-5.6 uses the effort selected by Claude Code; all user-level subagent overrides and every `claude -p` / `--print` SDK request use qwen3.8-max-preview with effort high
```

## Provider Profile Switching

The provider switch covers interactive main and picker aliases, `/compact` and autocompact, `claude -p` and Agent SDK traffic, ordinary/named/nested/workflow subagents, and stale explicit GPT/Qwen model IDs in resumed sessions. Every switch is fleet-wide across the Windows host, `devcontainer-ubuntu-2404`, and `win10-ltsc-docker`: one versioned profile, one generation, and one stable client key. Legacy fleet keys are rebound to the same group so already-open clients cannot bypass the switch. Hidden per-node profile overrides and the retired Hyper-V Qwen-only staging hook are forbidden. An offline or unregistered guest is marked `pending-reconcile` and receives the same profile and stable key when it becomes reachable.

Profiles:

- `anthropic-only`: native Claude Code subscription for every traffic class, with OpenAI and Alibaba fallback blocked. Version 4 upgrades the main/Opus slot and legacy Opus 4.8 aliases to Opus 5, sets the Claude Code context and auto-compact windows to the official 1M model window, and pins compact independently to Sonnet 5/low. Small-fast, delegated work, the Haiku picker slot, and stale Spark/Luna/mini IDs remain on Sonnet 5/high.
- `qwen-only`: Alibaba Token Plan only. Main, picker aliases, compact, Plan, small-fast, SDK CLI, and every delegated agent use `qwen3.8-max-preview`; automatic compact/Plan/SDK/agent work is `high`, while interactive `/effort` remains selectable. GPT, Claude, and provider fallbacks are empty and stale GPT/Claude identifiers force-map to Qwen.
- `alibaba`: strict Alibaba Token Plan only. The server-side `Europe/Moscow` window is `17:00` inclusive through `03:00` exclusive: main and Plan use `qwen3.8-max-preview` with `high`; outside it every request is forced to the live Alibaba model ID `deepseek-v4-flash-0731` with `high`. Compact, small-fast, SDK CLI, Explore, general-purpose, workflow agents, and every other delegated child use Flash even inside the window. The input aliases `deepseek-v4-flash` and `deepseek-v4-pro` both normalize to `deepseek-v4-flash-0731`; Pro is never an upstream target. The published catalog contains only Qwen 3.8 Max and DeepSeek V4 Flash, and GPT, Claude, and all automatic fallbacks are empty. This is the fleet-wide Alibaba toggle for the Windows host and both Hyper-V guests.
- `chatgpt-only`: version 5, OpenAI/Codex OAuth account only. Main/Opus is Sol. Every non-Plan delegated/picker/compact/small-fast route, including Fable, Sonnet, Haiku, verified Agent SDK traffic, and legacy Terra IDs, is forced to Luna/max. The built-in Plan agent alone routes to Sol/high through the server-side composite in `references/plan-agent-premium-routing.md`. Raw Terra-medium is not published, Luna is published as the delegated target, generic model and provider fallbacks remain empty, stale Claude/Qwen/GLM/DeepSeek/Terra IDs route to Luna, client context is `370000` with compact threshold `340000`, and persistent `CLAUDE_CODE_EFFORT_LEVEL` is removed so interactive `/effort` remains selectable.
- `hybrid-current`: GPT-5.6 Sol main and Plan (`high`), Qwen 3.8 Max/high for compact, small-fast, SDK CLI, picker aliases, and every delegated agent. It includes only the explicit terminal Alibaba quota fallback from automatic Qwen work to Sol.

Switch workflow:

1. Read `references/provider-profile-contract.md` and the requested JSON snapshot under `profiles/`.
2. Discover the Windows host and Hyper-V guests; validate Headroom, sub2api, the target account, OAuth state, and model availability without printing credentials.
3. Capture the stable-key binding and generation, atomically rebind the key, invalidate routing cache, and run a nonce-tagged Headroom probe before changing node display config.
4. On pre-commit probe failure, restore the old binding and prove the previous route. Never leave a partial profile active.
5. Increment generation and reconcile reachable nodes using `references/provider-fleet-reconcile.md`; mark offline nodes `pending-reconcile` for bounded boot/login self-heal.
6. Run `references/provider-route-verification.md` and correlate tagged `usage_logs` rows for main, stale-model, compact, generic SDK CLI, Plan, and nested-agent traffic.

Provider safety:

- Never copy Claude OAuth credentials to client nodes or enable cross-provider fallback in `anthropic-only`.
- Patch only owned model/env fields; preserve hooks, MCP servers, permissions, agent bodies, and unrelated settings.
- Never infer the live profile from the Claude statusline, `/v1/models`, health checks, or settings alone.
- A failed node reconcile is drift after proxy proof, not a reason to roll back a successful provider switch.

## Operating Rules

- Do not print OAuth tokens, API keys, refresh tokens, passwords, or copied auth files in chat.
- Before changing a failing stack, match the symptom against `references/session-failure-registry.md` and build one correlated trace from Claude Code through Headroom and sub2api to the selected provider. Do not diagnose from a terminal label, health endpoint, model catalog, source diff, or UI effort/context display alone. If the user asked for analysis/report only, stop after evidence and recommendations; do not run broad suites or mutate runtime state.
- Do not wait for the user to catch persistence regressions. For every install, repair, Docker compose, Headroom, embedding-server, cache, Postgres, Redis, or "make reusable" task, proactively audit persistence before claiming done. The required proof is `docker inspect` showing `Type=bind` for Headroom `/root/.headroom`, `/root/.cache/headroom`, `/root/.cache/huggingface`, sub2api `/app/data`, Postgres parent `/var/lib/postgresql`, and Redis `/data`, plus `CCR_STORE True <nonzero>` after memory traffic. If any state path is a Docker named volume, fix the compose/profile/scripts first, recreate only the affected services, rerun `scripts/verify-claude-code-sub2api.ps1`, sync the local skill, commit, and push when repo changes were made.
- Prefer request-time `/v1/messages` probes and `usage_logs.upstream_model` over `/v1/models` catalog output.
- Routing defaults are profile-owned and fleet-wide. `qwen-only` sends every class to Qwen with no GPT/Claude fallback, pins automatic compact/Plan/SDK/agent work to high, and leaves interactive `/effort` selectable. `alibaba` sends main and Plan to Qwen 3.8 Max/high and compact, small-fast, SDK CLI, and all delegated children to DeepSeek V4 Flash/high; it redirects stale DeepSeek Pro requests to Flash and publishes no Pro target. `hybrid-current` v2 sends delegated traffic and every verified `(external, sdk-cli)` child to Qwen/high while Plan alone is Sol/high. Under `chatgpt-only`, user-level agent frontmatter, Fable/Sonnet/Haiku picker slots, verified Agent SDK traffic, compact, and stale Terra requests are Luna/max; Plan alone is Sol/high. Raw Terra-medium must be hidden from the catalog and legacy Terra identifiers exact-mapped to Luna so stale clients cannot inherit the old medium route. The Windows host and both Hyper-V guests must share the same profile generation and stable key; do not create per-node provider overrides.
- `chatgpt-only` v5 has empty `model_fallbacks` and `automatic_model_fallbacks`, publishes `gpt-5.6-luna`, and routes every non-Plan automatic class to Luna/max. Luna is a real OpenAI/Codex target, not a fallback alias. Anthropic and Alibaba accounts remain forbidden.
- Claude Code 2.1.219 can emit the same `(external, sdk-cli)` User-Agent for both a standalone `claude -p` turn and a real `Agent(...)` child; the previously assumed `agent-sdk/...` discriminator is not reliable. In `chatgpt-only`, classify a generic child only when structured `system` contains both `cc_entrypoint=sdk-cli` and `cc_is_subagent=true` with a non-empty `metadata.user_id`. Standalone print remains on its selected GPT main, verified children are Luna/max, and only a structurally verified built-in Plan child is Sol/high. Never classify compact or agent roles from user messages, tool results, User-Agent alone, or whole-body substring search.
- Treat structured Agent/SDK-child traffic as delegated SDK traffic. Under `chatgpt-only` v5, the OpenAI group must set `messages_dispatch_model_config.sdk_cli_mapped_model=gpt-5.6-luna` and `sdk_cli_reasoning_effort=max`. sub2api applies this before provider classification for `claude-cli/... (external, sdk-cli...)` only when the request also carries the trusted child markers; this includes Agent SDK children and SDK-mode print calls. Ordinary `claude -p`/`--print` on Claude Code 2.1.219 reports `(external, cli)` and remains on the selected main model; do not weaken that boundary or Plan could be misclassified.
- A completed OpenAI Responses stream is not empty merely because `response.output_text.delta` is absent. Before retry/failover, reconcile the full text carried by `response.output_text.done`, `response.content_part.done`, `response.output_item.done`, and terminal `response.output`; deduplicate by `(output_index, content_index)`, append only a missing suffix, and fail closed on conflicts. Require the `F48` exact-shape test and `openai_messages.stream_terminal_text_recovered` runtime proof; never pay for a second generation to hide a bridge conversion loss.
- Apply the selected versioned profile on every OS that can launch Claude Code, not only on the machine that runs Docker. `claude-route` owns host and guest reconciliation, including the stable API key and generation marker. Do not use the old `HEADROOM_HYPERV_STAGE_QWEN_PROFILE`/`HEADROOM_HYPERV_QWEN_VM_NAMES` sidecar: it could overwrite a non-Qwen global switch. An offline guest remains `pending-reconcile`; restart already-open Claude processes after its later successful reconciliation.
- Treat `%USERPROFILE%\.local\bin\claude.cmd` as a higher-precedence runtime config when it contains `set "..."` model lines. `settings.json` and User env can both be correct while this wrapper silently restores Spark/Terra or another stale delegated model on every launch. Setup must run `scripts/sync-claude-wrapper-models.ps1`; verification must run it with `-CheckOnly`; final proof must be a real parent `Agent` invocation or Claude JSON `modelUsage`, not `claude --agent`, because `--agent` turns that definition into the main session and does not exercise `CLAUDE_CODE_SUBAGENT_MODEL` semantics.
- After `claude update`, compare `claude.exe`, any `claude-real.exe`, and the target invoked by `claude.cmd`. The updater writes the current native binary as `claude.exe`; provider reconciliation must retarget a legacy wrapper so it cannot keep launching an older renamed binary.
- Set picker Opus/Fable/Sonnet/Haiku defaults to Qwen high only for `qwen-only`/`hybrid-current`: `ANTHROPIC_DEFAULT_OPUS_MODEL=qwen3.8-max-preview`, `ANTHROPIC_DEFAULT_FABLE_MODEL=qwen3.8-max-preview`, `ANTHROPIC_DEFAULT_SONNET_MODEL=qwen3.8-max-preview`, and `ANTHROPIC_DEFAULT_HAIKU_MODEL=qwen3.8-max-preview`, with display name `Qwen 3.8 Max`. `chatgpt-only` is the exception: every visible picker slot is an OpenAI/Codex ID, with Sol as primary and Luna for delegated/Fast routing.
- Keep hidden group compatibility mappings from bare and dated Claude aliases (`opus`, `fable`, `sonnet`, `haiku`, `claude-opus-4-8`, `claude-sonnet-4-6`, `claude-haiku-4-5`, `claude-haiku-4-5-20251001`) to `qwen3.8-max-preview`. They must be applied before mixed-provider classification but omitted from `/v1/models`; this protects stale Hyper-V/Windows clients without reintroducing Claude models into the picker.
- Keep the single group fallback `qwen3.8-max-preview -> gpt-5.6-sol` for automatic compact and SDK-CLI routes. The handler may use it for the exact terminal Alibaba Token Plan quota class before response bytes or while every matching Qwen account has that persisted quota circuit open. A selected healthy Qwen account stays on Qwen; scheduler misses caused by concurrency/configuration plus transient 429/5xx, context, auth, model, and mid-stream failures must remain visible. Direct interactive Qwen selection never uses this automatic fallback. Account-level `compact_model_mapping` and `compact_model_fallbacks` stay empty.

## Workflow

1. Locate the exact Claude session/request, read `references/session-failure-registry.md`, classify the failing layer and incident ID, then inspect current state: `~/.claude/settings.json`, User env, Docker container health, group mapping, account `credentials` compact mappings, and account `extra.model_rate_limits`.
2. If installing or repairing Docker/Claude config, read `references/install-and-claude-config.md` and use the bundled setup script.
3. If the task touches persistence, embeddings, caches, Docker volumes, compose, setup, RTK, or "reusable" docs, run the host-bind audit before and after changes. Do not accept Docker named volumes as equivalent to host persistence. For RTK, require a real Claude Code Bash tool call that increments host `rtk gain` plus matching container totals; a manual container probe is not proof of automatic participation.
4. If changing models or compact routing, read `references/group-and-compact-routing.md`, patch `groups.messages_dispatch_model_config.compact_mapped_model`, and clear any stale OpenAI account `compact_model_mapping` / `compact_model_fallbacks` unless the user explicitly requests a legacy OpenAI-only compact fallback.
5. If OpenAI/Codex OAuth reports `unsupported_country`, read `references/openai-unsupported-country.md` before changing account state, model routes, or auth files.
6. If debugging limits or errors, read `references/troubleshooting.md` before changing DB state. Preserve non-quota reasons such as `upstream_404_model_not_found` unless deliberately re-probing that model.
7. Verify with `references/verification.md`: Headroom health/upstream, host bind mounts, sub2api health, GPT-5.6 probes through Headroom, Claude alias probes, and `usage_logs` mapping evidence.
8. Update this skill only after live verification when a model lineup, context window, persistence layout, or proxy behavior changes.
